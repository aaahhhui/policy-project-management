# 政府科创政策系统第一阶段设计规格

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 阶段名称 | 第一阶段：单一真实来源采集与 AI 初评闭环 |
| 需求基线 | `docs/product/2026-07-23-policy-project-management-prd.md` 已确认 P0 |
| 文档日期 | 2026-07-23 |
| 目标周期 | 5 个工作日 |
| 验收环境 | 本地 Docker Compose |
| 设计状态 | 已确认 |

本阶段是完整 P0 的第一个可运行增量，不代表 P0 全部完成。开发遇到 PRD 和本规格未覆盖的业务问题时，必须先说明问题、影响和可选方案，并在取得需求确认后再调整实现。

## 2. 阶段目标

交付一条真实、可运行、可测试的纵向闭环：

`内部账号登录 → 企业档案查看 → 来源配置 → 广东省工信厅真实采集 → 政策入库与追溯 → AI 多主体初评 → 政策中心查看`

第一阶段优先验证最关键的不确定性：

1. 真实政府网站能否稳定采集、解析和留痕。
2. 跨栏目政策能否正确去重并保留来源关系。
3. 政策正文变化能否形成版本而非覆盖历史。
4. AI 评估任务、数据结构和页面是否能够支持后续完整三层评估。

## 3. 第一阶段范围

### 3.1 本阶段交付

- 账号密码登录、退出、密码安全存储和基础 RBAC。
- 预置申报负责人和只读用户两类验收账号。
- 公司共享档案及北京、苏州、深圳经营主体档案只读展示。
- 政策来源新增、编辑、启停、手动采集和每日自动采集。
- 广东省工业和信息化厅专用采集适配器。
- “通知公告”和“项目资金”两个栏目最近 90 天的首次回溯采集。
- 后续每日增量采集。
- 政策详情解析、原始网页快照、附件下载和来源追溯。
- 跨栏目去重、内容版本识别和历史版本保留。
- 政策中心列表、分页、关键词/来源/日期筛选和政策详情。
- AI 异步任务、模拟适配器、三经营主体初评、汇总结论和评估历史。
- 采集任务、采集任务明细和必要的失败记录。
- 登录、企业档案和政策详情的基础移动端可读性。
- 本地 Docker Compose 运行与验收。

### 3.2 本阶段不交付

- 完整账号管理页面、账号创建、停用、密码重置和角色分配。
- 企业档案编辑和公开信息更新。
- 其他四个重点政策来源的正式适配器。
- 任意网站的通用自动采集。
- 单条政策链接录入和自定义网址采集。
- 硬规则、加权评分、评估规则管理和规则版本管理。
- 负责人确认或修改 AI 建议。
- 企业微信通知。
- 政策转项目、项目台账和项目状态历史。
- 完整操作审计页面。
- 连续登录失败临时锁定。
- 连续采集失败告警。
- 云服务器部署、域名、HTTPS、正式备份和恢复演练。
- 完整移动端交互验收。

其中，连续登录失败限制仍属于最终 P0 的 `AUTH-02`，只是延后到后续阶段，不从 P0 基线删除。

## 4. 技术结构

沿用已确认的技术栈：

| 层级 | 选型 |
|---|---|
| 前端 | Vue 3、TypeScript、Vite、Element Plus |
| 业务 API | Python、FastAPI |
| 数据访问 | SQLAlchemy 2、Alembic |
| 数据库 | MySQL 8.4 |
| 采集 | Scrapy |
| 定时任务 | APScheduler |
| AI | 可替换 AI 适配层；第一阶段默认模拟适配器 |
| 文件存储 | 本地独立文件卷 |
| 本地运行 | Docker Compose |

系统采用“模块化单体业务应用 + 独立采集运行区”：

- 业务 API 与采集程序共享数据模型和数据库。
- 采集程序独立运行，采集失败不得影响登录、企业档案和政策查看。
- AI 评估使用数据库任务记录异步执行，不引入 Redis 或独立消息队列。
- MySQL 保存结构化数据、任务记录和文件元数据。
- 原始网页快照和附件保存在独立文件卷中。

## 5. 用户与权限

### 5.1 申报负责人

- 登录和退出。
- 查看企业档案、政策及 AI 评估结果。
- 新增、编辑和启停来源。
- 手动触发广东省工信厅采集。
- 手动重试采集失败任务。
- 手动重试或重新执行 AI 评估。

### 5.2 只读用户

- 登录和退出。
- 查看企业档案、政策及 AI 评估结果。
- 不显示来源管理入口。
- 不能调用来源维护、采集触发或 AI 重评接口。

前端菜单控制和 API 权限校验必须同时存在。无权限接口统一返回明确的禁止访问响应，不能仅依赖隐藏按钮。

第一阶段连续登录失败只记录失败事件，不临时锁定账号。

## 6. 企业档案

导入以下现有种子数据：

- 公司共享档案。
- 北京经营主体。
- 苏州经营主体。
- 深圳经营主体。

数据来源为：

- `data/seed/enterprise-profile.initial.json`
- `docs/product-data/2026-07-23-enterprise-profile-initial-draft.md`

页面只读展示公司基本信息、业务方向、技术能力、产品，以及各经营主体的注册信息、资质、知识产权和研发数据。

缺失、候选或待核验字段必须使用明确状态展示，不得把候选数据显示为已确认事实。深圳主体的法人属性和统一社会信用代码不得写死为已确认值。

## 7. 政策来源

### 7.1 首个真实来源

| 项目 | 内容 |
|---|---|
| 来源名称 | 广东省工业和信息化厅 |
| 官网 | `https://gdii.gd.gov.cn/` |
| 通知公告 | `https://gdii.gd.gov.cn/zwgk/tzgg1011/index.html` |
| 项目资金 | `https://gdii.gd.gov.cn/xmzj1033/index.html` |
| 首次回溯范围 | 最近 90 天 |
| 后续频率 | 每日一次增量采集，默认东八区 02:00，可通过配置调整 |

两个栏目作为同一来源下的两个来源栏目管理。

### 7.2 来源管理规则

- 来源支持新增、编辑和启停。
- 添加和编辑使用右侧抽屉。
- 来源名称、官网地址、栏目地址和启用状态必须校验。
- URL 仅允许 `http` 或 `https`。
- 广东省工业和信息化厅标记为“已适配”。
- 其他新增来源默认标记为“待适配”。
- “待适配”来源可以保存和启停，但不能触发采集。
- 页面必须明确说明不能采集的原因。
- 同一来源已有运行中任务时，禁止再次触发。

## 8. 采集与入库流程

1. 手动触发或每日调度创建采集任务。
2. 首次运行读取两个栏目最近 90 天的列表和分页；后续运行按增量方式处理。
3. 为每个候选条目创建任务明细。
4. 抓取详情页并解析标题、文号、发布日期、申报截止日期、正文、原网址和附件。
5. 保存原始网页快照。
6. 下载附件并记录文件元数据和下载状态。
7. 执行标准化、去重和版本判断。
8. 在事务中写入政策、来源关系、内容版本和文件元数据。
9. 政策版本成功入库后创建 AI 评估任务。
10. 更新采集任务统计和最终状态。

政策中心只读取已成功解析并完成必要留痕的数据。

采集任务状态统一为：待执行、运行中、成功、部分失败、失败。首次 90 天范围按官网发布日期判断；发布日期缺失的条目仍保留任务明细并尝试解析详情，但在日期未确定前不进入成功政策列表。

## 9. 去重与版本

去重依次使用：

1. 标准化网址。
2. 标题、发布日期和文号组合。
3. 规范化正文内容哈希。

同一政策同时出现在“通知公告”和“项目资金”时：

- 只生成一条政策。
- 保留两个来源发现记录。
- 两个来源记录分别保存栏目、发现时间和原始网址。

已存在政策的正文发生变化时：

- 新增政策内容版本。
- 保留旧版本和旧快照。
- 详情页默认展示最新版本。
- 新版本成功后创建新的 AI 评估任务。
- 不允许直接覆盖历史正文。

## 10. AI 初评

### 10.1 触发

- 政策内容版本成功入库后自动创建异步 AI 评估任务。
- 采集请求不等待 AI 返回。
- 申报负责人可以手动重试失败评估或重新评估。

### 10.2 输入

每批评估固定关联：

- 政策内容版本。
- 北京、苏州、深圳经营主体档案快照。
- 提示词版本。
- AI 适配器和模型配置。

输入数据只允许包含公开信息和公司内部非保密信息。

### 10.3 输出

每个经营主体分别输出：

- 匹配度：高、中、低、无法判断。
- 匹配依据。
- 不满足或待核实条件。
- 风险点。
- 建议动作。

政策层面汇总为一个 AI 建议结论：

- 建议申报。
- 持续关注。
- 暂不建议申报。
- 无法判断。

评估结构同时包含政策摘要和关键申报条件。

### 10.4 展示

- 政策列表只显示一个当前结论。
- AI 评估尚未完成或评估失败时，当前结论为弱化样式的“待确认”。
- AI 评估成功后，当前结论切换为弱化样式的 AI 建议。
- 第一阶段没有人工确认，因此任何 AI 建议都不使用正式确认样式。
- 不并列显示“系统结论”和“负责人结论”。
- 政策详情展示政策摘要、关键条件、三主体评估结果、汇总结论、生成时间和评估批次。
- AI 评估区可以显示任务状态“评估失败”，但它是任务状态，不是第二个政策结论。
- 重新评估生成新批次，历史批次保留。

### 10.5 适配器与联调

- 第一阶段先使用固定 JSON Schema 的模拟适配器。
- 模拟适配器用于验证任务、数据关系、异常处理和页面展示。
- 真实 DeepSeek 的模型名称、地址、密钥和参数通过配置注入。
- 提供真实密钥后，可以在不修改业务逻辑的情况下切换适配器。
- 如果第一阶段结束时仍未提供密钥，只验收 AI 流程和数据结构，不验收真实模型输出质量。

## 11. 页面设计

### 11.1 系统框架

桌面端使用左侧导航和顶部用户区域。第一阶段开放：

1. 政策中心。
2. 企业档案。
3. 政策来源，仅申报负责人可见。

### 11.2 登录页

- 账号和密码输入。
- 登录按钮。
- 不提供注册入口。
- 不提供忘记密码或自助重置入口。
- 登录失败提示不暴露账号是否存在。

### 11.3 企业档案

- 公司共享档案摘要。
- 北京、苏州、深圳经营主体区域。
- 待核验字段状态。
- 第一阶段没有编辑入口。

### 11.4 政策来源

- 来源名称、启用状态、适配状态、最近采集时间、最近结果。
- 添加来源按钮。
- 编辑、启停和立即采集操作。
- 添加和编辑使用右侧抽屉。
- 待适配来源的采集操作禁用并显示原因。

### 11.5 政策中心

- 沿用已确认的列表布局。
- 支持关键词、来源和发布日期筛选。
- 支持分页。
- 展示政策名称、发布日期、截止日期、来源和当前弱化 AI 建议。
- 点击政策名称进入详情。

### 11.6 政策详情

同页连续展示：

1. 标题和当前弱化 AI 建议。
2. 发布日期、截止日期、来源栏目、原网址和采集时间。
3. 政策正文。
4. 原始网页快照入口。
5. 附件列表和下载状态。
6. 内容版本历史。
7. AI 摘要、关键条件、主体结果和汇总结论。
8. AI 历史批次和负责人重评入口。

### 11.7 移动端

第一阶段桌面端优先。登录、企业档案和政策详情必须在手机宽度下正常阅读，不得出现关键内容不可见或严重横向溢出。来源管理和完整移动端交互不进入第一阶段验收。

## 12. 异常处理

- 单篇政策解析失败不终止整批任务。
- 失败条目进入采集任务明细并保存原因。
- 正文或原始网页快照保存失败时，该政策不计为成功入库。
- 单个附件下载失败不阻止政策入库，但必须保留失败记录。
- 数据库写入使用事务，避免政策、版本和来源关系出现半成品。
- AI 失败不影响政策入库和查看。
- AI 失败显示明确状态，申报负责人可以重试。
- AI 响应不符合 JSON Schema 时，评估任务失败，不保存不完整业务结果。
- 每日采集失败第一阶段只记录，不发送企业微信告警。
- 用户页面展示可理解的错误信息，详细技术异常写入服务日志。

## 13. 测试策略

### 13.1 自动化测试

- 正确和错误密码登录。
- 两类角色的菜单和 API 权限。
- 来源新增、编辑、启停和待适配限制。
- 同一来源重复运行拦截。
- 两个来源栏目列表与分页解析。
- 政策详情、正文、发布日期和附件提取。
- 标准化网址和跨栏目去重。
- 内容变化形成新版本。
- 单篇解析、快照和附件失败的不同处理。
- 政策入库后自动创建 AI 任务。
- 模拟 AI 响应的 JSON Schema 校验。
- 三主体结果和政策汇总结论。
- AI 评估与政策版本、档案快照、提示词版本的关联。
- AI 重评保留历史批次。
- 只读用户不能触发 AI 重评。
- 前端登录、筛选、分页、详情、来源追溯和 AI 展示关键路径。

### 13.2 第一阶段验收

1. 申报负责人和只读用户均可登录，菜单和接口权限正确。
2. 公司及北京、苏州、深圳档案可查看，待核验字段标识正确。
3. 可以新增、编辑和启停来源；非广东省工信厅来源显示“待适配”。
4. 可以手动采集广东省工信厅两个栏目最近 90 天数据。
5. 每日定时采集可以通过调整执行时间在验收期间触发一次。
6. 采集任务和任务明细包含完整统计和失败原因。
7. 政策列表支持关键词、来源和日期筛选及分页。
8. 抽查至少 10 条政策，标题、发布日期、正文、来源网址、快照和附件与官网一致。
9. 跨栏目重复内容只生成一条政策，并保留两个发现记录。
10. 使用测试样本模拟正文变化，能够形成新版本并保留旧版本。
11. 政策入库后自动产生三主体模拟 AI 结果和一个汇总结论。
12. AI 重评产生新批次，旧批次仍可查询。
13. AI 失败不影响政策查看，负责人可以重试。
14. 手机宽度下登录、企业档案和政策详情正常阅读。
15. 如果验收前提供真实 DeepSeek 密钥，抽取 5 条政策进行真实接口冒烟联调。

第一阶段不以五来源 90% 覆盖率、企业微信通知、备份恢复、硬规则、加权评分或人工确认作为验收条件。

- 登录、基础 RBAC 和预置账号。

### 第 2 天

- 来源管理页面与接口。
- 广东省工信厅两个栏目适配器。

- 详情解析。
- 原始网页快照和附件。
- 去重、跨栏目来源关系和内容版本。

### 第 4 天

- 政策中心和政策详情。

## 15. 进度与变更原则

- 真实采集、来源追溯、去重和数据完整性优先级最高。
- 不自行削减已确认范围。
- 官网结构、附件格式或数据质量出现未覆盖问题时，先请求需求确认。
- 五日内出现进度风险时，先请用户选择延期或缩减范围。
- 新需求不得直接进入第一阶段，必须说明对周期、数据结构、测试和后续 P0 的影响。
